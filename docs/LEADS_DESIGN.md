# 检索系统业务设计：资质到期线索 + 电销跟进（公海/私海）

2026-11-23。采集系统阶段性结束后，下一步是给小团队用的检索系统：围绕「资质即将到期/已过期」的企业做电话咨询，推培训资料。本文从业务角度完善 Hu 的初步想法（检索 → 接单到个人 → 逐个联系 → 标记意向 → 接单过期回归），采用成熟电销 CRM 的公海/私海模型。数据底座是现有 Postgres：`company` + `qualification`（含 `expires_on` 到期日），检索系统即 `web/` 的业务化演进。

## 0. 先指出一个数据缺口：电话号码从哪来

平台公开数据里**没有联系电话**：现有采集的企业基础信息只有名称、信用代码、法人、注册类型、属地、地址、详情链接。打电话这个业务成立的前提是号码，所以系统必须有独立的「联系方式」层：

- 号码来源（按可靠性）：第三方工商数据（企查查/天眼查类，需另行采购/对接）、企业官网/公开渠道人工补录、历史成交客户留存。
- 数据模型：一个企业可挂多个号码（法人手机、座机、经办人），每个号码带来源、类型、有效性标记（可打通/空号/停机/错号）。成员通话后顺手标记号码质量，团队共享沉淀——这是这个业务最值钱的资产，比线索本身更持久。
- 设计含义：检索清单要能按「有可用号码」过滤；没有号码的企业进「待补号码」队列，不和可打的混在一起。

## 1. 核心概念修正：线索 = 企业 × 资质（到期事件）

Hu 原方案以「企业清单」为单位。更准确的单位是**一条资质到期事件**：

- 一家企业可能有多个资质、到期日各不相同；联系标记、意向都是针对某个资质的（Hu 原话也是「一个资质咨询后标记」）。
- 但**拨打按企业聚合**：打开一家企业，一通电话里把它的全部到期资质逐个问、逐个标记。减少重复打扰，也减少重复拨号。
- 所以有两层对象：**线索（lead）** = 企业×资质，是接单、状态、意向的单位；**拨打任务**按企业聚合呈现。

线索从哪来（自动生成，不靠人工建）：

- 规则扫描 `qualification` 当前版本：`expires_on` 落入窗口即生成线索。窗口分层（后台可配）：**已过期 / ≤30 天 / ≤90 天**，紧迫度即优先级，列表默认按到期日升序。
- 同一企业×同一资质（business_key）同时只有一条活跃线索，去重键现成。
- **与采集联动**：采集刷新后若该资质 `expires_on` 已推后（企业自己续期了）→ 线索自动关闭，关闭原因「已自行续期」，成员不用白打；企业注销/消失 → 线索自动关闭「企业注销」。这是采集+版本化数据独有的优势，必须用上。

## 2. 公海 / 私海与接单规则（防囤积是关键）

成熟做法不是「接单有效期」一个参数，而是按状态分级回收：

| 规则 | 建议默认 | 说明 |
|---|---|---|
| 持有上限 | 每人同时 ≤ 100 条活跃线索（可配） | 没有上限必然囤积，公海会被先到者掏空 |
| 接单方式 | 按筛选结果批量接（一次勾选/按量取 N 条）+ 单条接 | 逐条点太慢；批量接要有数量确认 |
| 未联系回收 | 接单后 3 天（可配）零联系记录 → 自动回公海 | 「接单有效期」主要管这一段 |
| 已联系保护 | 有联系记录后不按接单期回收，按跟进节奏走（见 §3） | 避免聊到一半被回收 |
| 主动释放 | 成员可随时退回公海（记原因） | 释放不算失败，鼓励流转 |
| 管理员 | 可强制回收/转派 | 处理离职、请假、囤积 |

可见性：线索被接单后对其他成员不可见（Hu 原方案），但**组长/管理员全局可见**，且企业详情页对其他人显示「已被同事跟进中」（只显示状态不显示细节），避免撞单又保留协作信息。

## 3. 联系结果体系：在「意向」之外补齐通话结果

Hu 的三档意向（拒绝/犹豫/成交 + 备注）是对的，但只覆盖「接通并谈了」的情况。真实通话先有**通话结果**，再有意向：

- **未接通**：无人接听/占线/关机 → 不算一次有效跟进，系统按规则自动排下次拨打（如次日），累计 N 次未接通（如 5 次，可配）自动回公海或转「低优先」。
- **号码无效**：空号/停机/错号 → 标记号码失效（沉淀到号码层），该企业无其他号码则线索转「待补号码」。
- **接通后意向**（每档都带备注框，沿用 Hu 的设计）：
  - **拒绝**：分软/硬。软拒绝（不需要、已有渠道、时机不对）→ 进冷却期（默认 90 天可配），冷却结束可回公海换人再试；硬拒绝（明确要求勿再联系）→ 进**勿扰名单**，全团队永久生效，该企业所有线索关闭。
  - **犹豫**：**必须选下次回访时间**（这是犹豫和变相拒绝的区别）。到回访日进本人「今日待办」；逾期未访有提醒；连续逾期超限才回收。
  - **成交**：意向之外记**成交产品（哪套培训资料）+ 金额**，线索关闭为成交；同时把该企业转为「客户」：其资质下个周期到期时自动生成新线索，并**优先回到原成交人名下**（老客户复购是这类业务最稳定的来源，归属规则要先定）。

每次联系生成一条**跟进记录**（时间、通话结果、意向、备注、下次回访），线索详情是时间线，不只存最后状态——组长复盘和交接都靠它。

## 4. 成员工作台（日常动线）

成员每天打开的不是检索页，而是**今日待办**：

1. 今日待回访（犹豫到期）
2. 今日新接未联系（按到期紧迫度排序）
3. 未接通待重拨
4. 已逾期（红色置顶）

检索/公海页是「补货」用的：按地市、资质类别/名称、到期窗口、有无号码筛选，批量接单。拨打在企业聚合页完成：号码列表（点号码即标记本次拨打对象）、名下全部到期资质逐个标记结果，一次提交。

## 5. 角色与后台配置

- 角色：成员（只见公海 + 自己私海）、组长（全团队可见、转派、看统计）、管理员（配置 + 账号）。
- 后台可配项：到期窗口分层、接单有效期（未联系回收天数）、持有上限、未接通重拨规则与上限、软拒绝冷却期、犹豫回访逾期上限、勿扰名单管理、意向/产品字典。
- 统计看板（组长）：线索池存量与流转、每人接单/联系/接通/成交数、意向分布、回收率（囤积监控）、号码有效率。先做简单计数页即可，不做复杂 BI。

## 6. 数据模型增量（在现有库上加，不动采集表）

- `lead`：id、credit_code、qualification business_key、expires_on 快照、紧迫层、状态（公海/已接单/跟进中/已成交/已关闭）、关闭原因、owner、claimed_at、claim_expires_at、next_follow_at、冷却至、created/updated。唯一约束：(credit_code, business_key) 活跃线索至多一条。
- `contact_record`：lead_id、企业、操作人、通话结果、意向、备注、产品/金额（成交时）、下次回访、created_at。
- `company_phone`：credit_code、号码、类型、来源、有效性、标记人/时间。
- `do_not_call`：credit_code（或号码）、原因、登记人、时间。
- `app_user` + `system_config`（键值，后台可改）。

## 7. 分期

- **MVP**：线索自动生成（到期窗口扫描 + 续期自动关闭）、公海检索（地市/资质/窗口/有无号码）、批量接单 + 持有上限 + 未联系回收、 企业聚合拨打页、通话结果+三档意向+备注+回访时间、跟进时间线、今日待办、勿扰名单、号码补录与有效性标记、后台配置页（有效期/上限/窗口）。
- **V2**：统计看板、成交产品/金额与客户复购线索、未接通自动重拨队列、号码批量导入（第三方数据）、组长转派与囤积预警。

## 8. 待 Hu 拍板的决策点

1. **号码来源**：先人工补录起步，还是直接对接第三方工商数据？（决定 MVP 排期）
2. **成交记账深度**：只记产品+金额做统计，还是要管交付/收款状态？（建议先只记账）
3. **持有上限与未联系回收天数**：先给默认 100 条 / 3 天，上线后按实际节奏调。
4. **老客户归属**：成交客户下周期线索优先原成交人（建议是），保护期多久？
